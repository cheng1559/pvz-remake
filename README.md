## 🌻 Overview

PvZ Remake is an open-source remake of the PC version of *Plants vs. Zombies*. It follows the Steam Game of the Year edition, version 1.2.0.1096, is written in TypeScript on Cocos 4, and runs in the browser and on Windows, macOS, Android and iOS. The project aims to rebuild and extend the original on a modern technology stack: a cross-platform, more stable game for players, and an easier, more consistent way for the community to build on it.

The current version is v0.2.0, with all 20 Day and Night levels of Adventure mode. Besides restoring the original gameplay, the project fixes a number of presentation and logic problems in the original and adds teams, a debug console and Mod support, described below.

## 🎮 How to Play

### Play Online

The web version is the project's web build, hosted at [plants-vs-zombies.cc](https://plants-vs-zombies.cc). It runs in desktop and mobile browsers and can be installed to the desktop or home screen as a PWA.

Player profiles, level saves and settings are kept in the browser's localStorage, and installed Mods and resource packs in IndexedDB. Clearing the site's data deletes all of them, and nothing is synchronized between devices.

### Download a Release Build

[Releases](https://github.com/cheng1559/pvz-remake/releases) provides builds for each platform.

### Build It Yourself

Building the game requires these files from a licensed copy of the *Plants vs. Zombies* Steam Game of the Year edition (1.2.0.1096), placed in `tools/`:

| File | Resources it provides |
| --- | --- |
| `main.pak` | Images, animations, particles, fonts, sound effects, music and text |
| `PlantsVsZombies.exe` | Resources built into the program: the mouse cursors and the app icon |

Note that the files of 1.2.0.1073 also build, but in its `main.pak`, `properties/LawnStrings.txt` lacks part of the interface text and `images/acheesements_icons.png` lacks the Disco is Undead icon, so some text and images display incorrectly:

- Achievement names and descriptions on the achievements and award pages show as text keys;
- Almanac entry titles show as text keys;
- Dialog buttons, the pause menu, the options and the player profile screens show text keys;
- The Disco is Undead achievement icon is blank;
- With the Chinese resource pack enabled, the text above still cannot be shown in Chinese.

The import command converts the resources and builds the base content package; the app icons are generated by a separate icon command. See [Development and Builds](#-development-and-builds) for the full steps.

## ✨ New Features

### Mods

A Mod is an extension package installed into the game. The base game is itself a Mod, with the same format and loading as any other, so Mods can change any part of the game. Common kinds of Mods:

- **Resource replacement**: HD art, new art styles, translations, new music;
- **Balance changes**: plant and zombie stats, level waves and spawns, store prices and so on;
- **New content**: new plants, zombies, projectiles, levels and achievements;
- **Gameplay changes**: different planting or collecting rules, or new level rules and screens.

Several Mods can be enabled at once and stack. For example, with the HD pack and the Chinese pack enabled together, the Chinese pack replaces only the images with text in them, and the other images still come from the HD pack. A Mod can change other Mods' definitions or translate them. Data a Mod records is kept in level saves.

| [Widescreen Edition music](https://github.com/cheng1559/pvz-remake/releases/tag/mod-hd-bgm-0.1.0) | The music of PvZ Widescreen Edition in place of the game's tracks |
| [JiangNan PvZ2 pack](https://github.com/cheng1559/pvz-remake/releases/tag/mod-jiangnan-pvz2-0.1.0) | The art, animations and sounds of JiangNan Game's *PVZ2PAK GOTY edition* |
| [Chinese pack](https://github.com/cheng1559/pvz-remake/releases/tag/mod-zh-cn-0.1.0) | Simplified Chinese text, fonts and interface images, translated as in the official Chinese GOTY edition |
| [HD pack](https://github.com/cheng1559/pvz-remake/releases/tag/mod-hd-0.1.0) | HD resources: every image at 2x and bitmap fonts at 4x |
| [Chinese HD pack](https://github.com/cheng1559/pvz-remake/releases/tag/mod-zh-cn-hd-0.1.0) | The HD resources and Simplified Chinese in one package, usable alone |
| [Extra buttons pack](https://github.com/cheng1559/pvz-remake/releases/tag/mod-dlc-buttons-0.1.0) | Adds speed and freeze buttons and turns the seed chooser's page text into arrow buttons |

#### How It Works

- **One package format**: every extension is a Mod, and the base game is a built-in package with the ID `pvz`. A resource pack holds only resources and needs no scripts; a scripted Mod can carry server scripts (gameplay) and client scripts (presentation).
- **Load order**: Mods load from the bottom of the manager's list to the top. When several Mods provide the same resource, the one higher in the list wins.
- **Namespaces**: resources and definitions a Mod adds must use its own namespace (such as `widescreen:background1`). An entry written under an existing ID changes that definition field by field; when two Mods change the same field, the one loaded later wins.
- **Text**: all text is merged into one table. A Mod can rewrite any existing text, and new text needs its namespace. A translation pack lists only the entries it changes, and can translate other Mods too.
- **Load checks**: loading checks that content is complete, for example that every plant and zombie has a look and every level award has a picture. An incomplete Mod fails to load instead of failing later in a level.
- **Error recovery**: when a Mod fails during play, an error dialog opens, from which the Mod manager can disable the failing Mod before restarting.
- **Storage**: the web version keeps Mods in IndexedDB, native versions in `mods/` in the app data directory. Each player profile keeps its own installed Mods, versions, enabled states and order; a ZIP with the same content is stored once per device.

#### Using Mods

1. On the main menu, click Options and then Mods to open the Mod manager, or run `/mod`.
2. Click Import and choose ZIP files; several can be chosen at once.
3. Tick the Mods to enable and use the arrows to order them.
4. Click Apply and confirm the restart. The game saves the current level first and finishes installing, uninstalling and enabling on the next start.

Cancel discards the imports and ordering. Reordering only disabled Mods needs no restart. Switching to a profile with different Mods enabled offers a restart, and a new profile can copy the current profile's Mods.

#### Developing Mods

Every Mod has two files at its root:

- `manifest.json`: the Mod's ID, version and script entry points, if any;
- `content.json`: the index of its gameplay definitions, presentation definitions and resources.

```sh
npm run mod:init -- my-mod          # create a Mod from the template
npm run mod:pack -- mods/my-mod     # compile and pack it as a ZIP in dist/mods/
npm run mod:test -- my-mod          # pack it and check its server registration
```

Mods can extend the game in these ways, a design modelled on Fabric API and Mixin from Minecraft modding:

- **Data definitions**: add plants, zombies, projectiles, seeds, levels, store items and achievements in JSON, or replace existing definitions.
- **Registration** (like Fabric API): the script entry point `register({ host, assets })` gets game modules through `host.get()` and adds new plant, zombie and projectile kinds to the registries, with their views, debug commands, achievement triggers, level rules and tutorial scripts. A new kind extends one of the base game's classes and is chosen in a definition's `kind`.
- **Method wrapping** (like Mixin): `host.around()` wraps a server rule function, adding handling before or after the original logic or replacing its result; the game's own calls go through the wrapper too.

```ts
export function register({ host, assets }) {
    // Register a new plant kind
    const registry = host.get('gameplay/registry')
    const { Shooter } = host.get('server/plants/Shooter')
    registry.plants.register(assets.id, 'example:rapid_pea', regenerating(Shooter))

    // Wrap a planting rule
    const { planting } = host.get('server/seeds/planting')
    host.around(planting, 'seedAvailability', function (next, session, seedId, ...rest) {
        return next(session, seedId, ...rest)
    })
}
```

The [Mod Lab](mods/example/README.md) example shows new plant and zombie kinds, entity data and saves, level changes, resource replacement, custom views, commands on both sides and menu extensions. See [Mods](docs/MODS.md) for the full guide.

### Debug Console

A built-in debug console tests levels, changes the game's state and switches display options. Press `/` on desktop or double-tap the bottom-right corner on mobile; it is unavailable during startup. The game pauses while the console is open and returns to its previous state when it closes.

The leading slash is optional and names ignore case. Tab completes commands and installed content names, and the Up and Down keys recall the last 64 commands. Rows, columns and seed slots count from 1. A malformed argument flashes the input red and keeps it open; an unmet condition (such as not being in a level) closes the console and shows the reason.

Switches take no argument: each run turns the switch over and shows its new state on screen. Switches and settings are kept on the device across restarts, except `/mobile`, `/perf` and `/gamespeed`, which last for the session, and `/fullscreen`, `/music` and `/sfx`, which are the settings in Options.

**Pages and levels**

| Command | Effect |
| --- | --- |
| `/goto {page}` | Opens a page: `main`, `minigames`, `puzzle`, `survival`, `almanac`, `plants`, `zombies`, `store`, `garden`, `mushroom`, `aquarium`, `tree`, `achievements`, `help` |
| `/level {level}` | Enters a level, such as `/level 2-10`, skipping the prompt about an existing save |
| `/restart` | Restarts the current level |
| `/reload`, `/quit` | Reloads or quits the game |

Three test levels do not overwrite the Adventure save: `pvz:teams-demo` (the teams demo), `pvz:stress-test` (40 plants against 1023 zombies) and `pvz:seed-chooser-test` (the seed chooser).

**Combat**

| Command | Effect |
| --- | --- |
| `/gamespeed {0-10}` | Sets the game speed; `0` freezes the game |
| `/win`, `/lose` | Wins or loses at once |
| `/nextwave` | Spawns the next wave at once |
| `/nextflag` | Skips to the next flag wave and starts its warning; run again during the warning to spawn it at once |
| `/repick` | Chooses seeds again during a level; kept seeds keep their recharge and new ones are ready. Not on conveyor-belt levels |

**Plants, zombies and the lawn**

| Command | Effect |
| --- | --- |
| `/plant {plant} {row} {col} [team]` | Plants in a cell directly, ignoring sun, recharge and occupancy |
| `/removeplant {row} {col}` | Removes the plant in a cell |
| `/zombie {zombie} [row] [col] [team]` | Places a zombie; without a row, the level's spawn rows decide |
| `/damage {damage}` | Damages the zombies on the lawn |
| `/kill` | Kills every zombie on the lawn |
| `/griditem {grave\|crater} {row} {col} [team]` | Places a grave or crater, replacing any grave or crater in the cell and clearing its plants |
| `/gravezombies` | Makes every grave raise a zombie at once |

**Seeds, resources and achievements**

### Teams

The original marks a zombie fighting for the player with a single "mind-controlled" flag, checked separately in more than twenty places. The remake uses teams instead: every plant and zombie belongs to the plants' side or the zombies' side, different sides are hostile, and every attack, bite and win check asks only whether two things are hostile. By default plants are on the plants' side (the player's) and zombies on the zombies' side, which plays exactly as the original.

**Facing and movement**

- The zombies' side faces left and the plants' side faces right; projectiles, blast areas and bowling directions mirror with them.
- Zombies on the plants' side walk right and disappear past the right edge of the lawn; zombies on the zombies' side that reach the house lose the level.

**Interactions**

| Situation | Rule |
| --- | --- |
| Plant attacks | Shooters, the Fume-shroom, the Chomper, the Potato Mine and bowling nuts hit only hostile plants and zombies, never their own side |
| Projectiles hitting plants | They take health straight off and flash the plant white; they fly over low plants such as the Puff-shroom and the Potato Mine, which shooters do not aim at, though area attacks still hit them |
| Chomper | Can swallow a hostile plant whole |
| Potato Mine | Its trigger and blast reach half a cell further forward against hostile plants |
| Zombie bites | A zombie looks for a hostile zombie in front first, then a hostile plant; it never bites its own side's plants |
| Chill and freeze | The Snow Pea's chill and the Ice-shroom's freeze act only on the hostile side, and work on plants too: a chilled plant shoots, produces and counts down at half speed, and a frozen one stops entirely |
| Lawn mowers | Crush only the hostile side |
| Shovel | Digs up only your own side's plants |
| Graves and backup dancers | Zombies raised by a grave, and backup dancers called up by a Dancing Zombie, take their summoner's side |
| Waves and winning | Count only zombies on the zombies' side |

**Hypno-shroom**

When a hostile zombie bites an awake Hypno-shroom, the zombie joins the Hypno-shroom's side and turns purple. A hostile Chomper that bites it turns too (plants never eat plants in the original). If the zombie that turns is the last hostile zombie on the lawn, the level award drops at once.

**Setting a side**

- The Hypno-shroom;
- The team argument of debug commands, such as `/zombie normal 3 1 plants` and `/plant peashooter 3 9 zombies`;
- Seed packets with a team, such as `/seed 1 snowpea zombies`;
- Units placed in a level's data.

Only units controlled by a Hypno-shroom turn purple; units placed on the other side keep their colors and only change facing. The project also adds zombie, grave and crater seeds, which go in seed slots like plants.

`/level pvz:teams-demo` opens the teams demo: nine zombies' side plants on the right fight the player's plants while four waves of zombies come from the right.

See [Teams and the Hypno-shroom](docs/TEAMS.md) for the full rules.

## 🏗️ Architecture

### Client and Server

The game is split into a client and a server. In single-player both run in the same process and talk through messages:

- **The server** owns every gameplay rule: plants, zombies, projectiles, waves, sun and winning or losing. Combat advances in fixed steps, 100 a second, the original's logic rate.
- **The client** owns input, graphics, animation, particles, sound and the interface. It never changes the game state itself: it sends the player's actions (choosing seeds, planting, collecting sun and so on) to the server as commands, and draws from the state snapshots and events the server returns. The client interpolates the picture between two logic steps, so it stays smooth on high refresh rate displays.

A level save holds the server's state (including its random number state) and the client's presentation state, so a loaded game continues exactly where it stopped. Keeping the rules on the server also lays the groundwork for multiplayer.

```mermaid
flowchart LR
    Input[Player input] --> Client[Client]
    Client -- Commands --> Server[Server<br/>100 steps a second]
    Server -- Snapshots and events --> Client
    Client --> Output[Graphics and sound]
```

### Data-driven Content

Plants, zombies, projectiles, seeds, levels and waves, the store and achievements are all defined in JSON, as gameplay definitions (numbers and rules) and presentation definitions (animations, positions and sounds). Tuning numbers or adding content usually means changing data, not code.

The base game is itself a content package (`pvz-base`), with the same format and loading as Mods. A Mod can change base definitions or add its own; for new behavior, it registers its own plant or zombie kind and refers to it from its data.

Art, animations, particles, fonts, sounds and text are converted from the licensed game's resources at build time; the repository contains no original assets.

See [Architecture](docs/ARCHITECTURE.md).

## 🛠️ Development and Builds

### Setup

The project uses two forked repositories, both on the `dev/pvz-remake` branch:

| Repository | Role |
| --- | --- |
| [cocos-cli](https://github.com/cheng1559/cocos-cli/tree/dev/pvz-remake) | The command-line tool for previews, builds and native packaging |
| [cocos4](https://github.com/cheng1559/cocos4/tree/dev/pvz-remake) | The game engine, with this project's changes for native platforms |

Requirements:

- Node.js 22.17.0 and `node-gyp`;
- Python 3.10 or later, with Pillow, ffmpeg and libopenmpt (to convert the game's resources);
- For native builds, the platform's development tools, such as Xcode for macOS and iOS.

Install the command-line tool outside the game repository, with the engine in its `packages/engine` directory:

```sh
git clone --branch dev/pvz-remake https://github.com/cheng1559/cocos-cli.git
cd cocos-cli
git clone --branch dev/pvz-remake https://github.com/cheng1559/cocos4.git packages/engine
git clone --depth 1 --branch v4.0.0-10 https://github.com/cocos/cocos-engine-external.git packages/engine/native/external
npm install -g node-gyp
npm run install:engine
npm install
npm run build
npm link
```

### Importing Resources and Previewing

Put the game files in `tools/` as described in [Build It Yourself](#build-it-yourself), then run from the game repository's root:

```sh
npm ci
npm run build:content     # convert the game's resources, about 9 minutes
npm run build:icons       # generate the app icons (optional)
npm run preview:debug     # start the preview, http://localhost:9527 by default
```

### Common Commands

| Command | Effect |
| --- | --- |
| `npm run test:server` | Server typecheck and every test |
| `npx tsc --noEmit -p tsconfig.json` | Client typecheck |
| `npm run test:tools` | Tests of the resource conversion tools |
| `npm run mod:pack -- pvz-base --publish assets/resources/base.zip` | Repacks the base content after changing its definitions, without converting resources again |
| `npm run mod:pack -- mods/{mod}` | Packs a Mod |

### Release Builds

| Platform | Command | Output |
| --- | --- | --- |
| Web | `npm run build:web:release` | The web build |
| Windows | `npm run compile:windows:release`, then `npm run package:windows` | The installer `dist/pvz-remake-v{version}-windows-x64-setup.exe`; packaging needs Inno Setup 6 |
| macOS | `npm run compile:macos:arm64:release` and `compile:macos:x64:release`, then `npm run package:macos` | The disk images `dist/pvz-remake-v{version}-macos-arm64.dmg` for Apple silicon and `-macos-x64.dmg` for Intel Macs; macOS only |
| Android | `npm run compile:android:arm64:release` | An arm64 package; use `android:armv7` for 32-bit devices |
| iOS | `npm run compile:ios:release` | An unsigned IPA to sign yourself; macOS only |

Replace `release` with `debug` in a command for a debug build. The Windows installer packs only a Release build.

## 🐛 Bug Fixes

The following problems exist in the original 1.2.0.1096 and are fixed in this project. Presentation problems affect only graphics and sound, never the outcome; logic problems affect how the game plays or ends.

### Presentation

1. Fixed the main menu tombstone button switching only after the intro animation. In the original, the tombstone shows Start Adventure throughout the intro and changes to Adventure and the level progress only when it ends.
2. Fixed the size of the Sun-shroom's shadow in the almanac. The original shows a grown Sun-shroom with a seedling's shadow.
3. Fixed Crazy Dave's arm being hidden behind the car's taillights (the page buttons) as he enters the store.
4. Fixed the size of the Dancing Zombie and Backup Dancer previews in the almanac, now matching the lawn.
5. Fixed the Dancing Zombie and Backup Dancer sliding into the house in a dance pose such as a raised arm; they now switch to walking.
6. Fixed the sod roll sound looping for as long as the game is paused during the opening sod roll.
7. Fixed the direction of the heads, arms and flags dropped by zombies under a Hypno-shroom's control; they now fly the way the zombie faces.
8. Fixed the spotlight of a Dancing Zombie under a Hypno-shroom's control sitting off its body.
9. Fixed the Backup Dancer's head flying off slightly larger than it was on its body.
10. Fixed the Dancing Zombie's and Backup Dancer's shadows being smaller than other zombies'.
11. Fixed the Dancing Zombie facing the wrong way after eating during its moonwalk: for a frame, or walking backwards.

### Logic

1. Rewrote scrolling to move by the scroll amount, fixing abnormal touchpad scrolling speed.
2. Fixed several Pole Vaulting Zombies that have vaulted in one row shrinking the Potato Mine's trigger range cumulatively, until it may not go off at all (the "four pole vaulters" trick).
3. Fixed the Dancing Zombie's dance beat advancing while the game is paused, which let pausing steer the dance (the "maid" cheat). The beat now follows the level's time.
4. Fixed a Flag Zombie's leftover flag animation ID deleting another object's animation (Flag Reanimation Skip, FRS). In the original, this could make Squashes immune to being eaten and other abnormal states.
5. Fixed Whack a Zombie never dropping its award, so the level could not end, when the last group arrives after every grave has been eaten by Grave Busters and no zombie is left on the lawn.
6. Fixed the game stopping while its window is dragged or resized.
